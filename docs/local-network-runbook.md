# Local Network Runbook

이 문서는 센터 내부에서 autoPAN을 일상 운영할 때 필요한 최소 절차를 정리한다.

## 장비 역할

- 서버 PC: Next.js 앱과 PostgreSQL을 계속 실행
- 관리자 PC: `/admin` 접속
- 키오스크 태블릿: `/kiosk` 접속
- 대기 보드 화면: `/board` 접속

## 매일 시작할 때

1. 서버 PC 전원을 켠다.
2. `systemctl status autopan`과 `systemctl status caddy`를 확인한다.
3. 보드 화면이 열리는지 확인한다.
4. 관리자 PC에서 접수 생성과 대기열 갱신이 되는지 확인한다.
5. 백업 디렉터리에 전날 백업이 있는지 확인한다.

## 운영 중 확인할 것

- 서버 PC가 절전 모드로 들어가지 않도록 설정한다.
- 네트워크가 끊기면 먼저 서버 PC가 아니라 공유기와 케이블을 확인한다.
- 화면이 느려지면 관리자 화면과 보드 화면의 탭 수를 줄인다.
- TTS가 겹치면 보드 화면을 새로고침해서 재생 상태를 정리한다.

## 주소 접속 규칙

- 가능하면 서버 IP를 고정하거나 DHCP 예약을 사용한다.
- 모든 단말은 같은 LAN에서 서버 IP로 접속한다.
- 예시:

```text
http://192.168.0.10/
http://192.168.0.10/kiosk
http://192.168.0.10/admin
http://192.168.0.10/board
```

## 장애가 생겼을 때

1. `systemctl restart autopan`
2. `systemctl restart caddy`
3. `journalctl -u autopan -n 50 --no-pager`
4. `journalctl -u caddy -n 50 --no-pager`
5. 그래도 안 되면 서버 PC를 재부팅한다.

## 종료할 때

1. 오늘 백업이 생성됐는지 확인한다.
2. 관리자 화면에서 미완료 세션이 남아 있는지 확인한다.
3. 다음날 아침 자동 기동이 될지 확인한다.
4. 특별한 문제가 있으면 운영 로그에 남긴다.

## 금지 사항

- 학생에게 서버 PC를 직접 만지게 하지 않는다.
- 서버에서 개발 모드로 운영하지 않는다.
- 백업 없이 장기 운영하지 않는다.
