autoPAN 기본 설계서

나놀다판 현장 운영을 종이 접수와 수기 스프레드시트에서 키오스크, 관리자 화면, 대기 보드 중심의 운영 시스템으로 전환하기 위한 요구사항, 기능정의, 객체지향 설계, 상태 흐름을 한 화면에서 설명한다.

대상: 노원청소년센터 나놀다판 범위: v1 운영 자동화 구현: Next.js + TypeScript 저장소: 메모리 데모 + PostgreSQL 확장 준비

1. 요구사항 요약

문제 정의

  • 접수, 대기, 결제, 입장, 종료 정보가 분리되어 있다.
  • 학생은 다음 행동을 바로 알기 어렵다.
  • 관리자는 대기열과 현재 이용 상태를 동시에 보기 어렵다.
  • 호출과 안내가 사람 의존적이라 누락 가능성이 있다.

제품 목적

  • 키오스크에서 학생 또는 보호자가 직접 접수한다.
  • 유료 콘텐츠와 공간 이용을 명확히 분리한다.
  • 자원별 대기열, 호출, 결제 확인, 시작, 종료를 연결한다.
  • 관리자는 서울시 결제시스템 처리 결과만 운영 상태에 반영한다.

운영 제약

  • 실제 결제 승인은 시스템이 직접 수행하지 않는다.
  • 결제와 세션 시작은 반드시 별도 단계다.
  • 공간 이용은 대기열, 세션, 매출 집계에서 제외한다.
  • 키오스크는 30초 무반응 시 첫 화면으로 복귀한다.

3. 사용자 흐름

1. 접수 시작 첫 방문 또는 재방문을 선택하고 회원 정보를 확인한다.
2. 자원 선택 PC, 닌텐도, 플레이스테이션, 공간 이용 중 하나를 선택한다.
3. 대기 판단 유료 콘텐츠는 빈 자리와 기존 대기열을 기준으로 즉시 이용 또는 대기 등록으로 나뉜다.
4. 관리자 처리 관리자가 서울시 결제시스템에서 결제 후 시스템에 결제 기록과 시작 처리를 남긴다.
5. 종료/리포트 세션 종료, 연장, 노쇼, 일마감 리포트가 운영 데이터로 축적된다.

4. 태블릿 키오스크 접수 방식

현재 단계

어떤 이용을 할까요?

태블릿에서는 이전 단계의 입력 영역을 아래에 남기지 않고, 다음 단계 화면으로 완전히 전환한다.

PC 이용
닌텐도 이용
플레이스테이션 이용
공간 이용

단일 단계 화면

접수 흐름은 여러 입력 묶음을 한 화면에 동시에 노출하지 않는다. 사용자가 다음을 누르면 이전 단계 아래로 새 단계가 붙는 방식이 아니라, 현재 화면이 다음 단계 화면으로 교체된다.

상단 작은 뒤로가기

이전 단계로 돌아가는 기능은 화면 상단에 작은 보조 버튼으로 둔다. 주 동선은 항상 현재 단계의 큰 선택 버튼 또는 다음 버튼이 되도록 한다.

태블릿 터치 기준

선택지는 손가락으로 누르기 쉬운 큰 버튼으로 만들고, 한 화면의 선택지는 2개에서 4개 수준으로 제한한다. 긴 설명보다 선택 가능한 행동을 먼저 보여준다.

입력값 유지

뒤로 이동하면 직전 단계에서 입력한 값은 유지한다. 다만 30초 무반응 자동 복귀가 발생하면 미완료 접수 값은 버리고 첫 화면으로 돌아간다.

5. 화면 설계

홈 /

  • 오늘 운영 상태 요약
  • 키오스크, 관리자, 보드 화면 진입
  • 현재 활성 세션과 대기 규모 확인

키오스크 /kiosk

  • 학생/보호자 셀프 접수
  • 한 화면에는 현재 접수 단계 하나만 표시
  • 다음 단계 진입 시 화면 전체를 다음 단계로 전환
  • 이전 단계 이동은 상단의 작은 뒤로가기 버튼으로 처리
  • 30초 무반응 자동 복귀

관리자 /admin

  • 대기열, 호출, 결제 기록, 시작/종료 관리
  • 연장, 노쇼, 재대기 처리
  • 리포트와 운영 설정 확인

6. 객체지향적 요소

현재 구현은 TypeScript 인터페이스와 서버 도메인 함수 중심이다. 각 인터페이스가 엔터티 역할을 하고, 저장소와 상태 변경 함수가 책임을 분리한다.

구현체: DemoRepository
객체지향 개념 현재 설계에서의 대응
캡슐화 상태 변경은 store.ts의 함수로 모아 직접 배열 조작을 화면 컴포넌트에 노출하지 않는다.
추상화 StoreRepository 인터페이스가 저장소 접근을 추상화하여 메모리 저장소에서 PostgreSQL 저장소로 바꿀 수 있다.
단일 책임 도메인 타입은 domain.ts, 상태 계산은 state.ts, 변경 유스케이스는 store.ts, API 라우팅은 route.ts에 둔다.
확장성 자원 종류, 요금제, TTS 이벤트, 결제 단계가 타입으로 분리되어 v2 기능을 추가하기 쉽다.

7. 상태 전이 다이어그램

방문 상태

queued → awaiting_payment → in_session → completed

예외: canceled, no_show

대기 상태

waiting → ready → seated

예외: ready → no_show → waiting

세션 상태

active → ended

연장은 상태 변경 없이 종료 예정 시각과 누적 시간을 갱신한다.

8. 시스템 구조

Presentation Layer

  • /kiosk: 접수 전용 UI
  • /admin: 운영자 관리 UI
  • /board: 대기 번호와 TTS 출력
  • useLiveSnapshot: 3~5초 폴링 동기화

Application Layer

  • GET /api/state: 전체 운영 스냅샷 조회
  • POST /api/mutations: 상태 변경 명령 처리
  • validation.ts: Zod 입력 검증
  • store.ts: 접수, 결제, 시작, 종료 유스케이스

Domain/Data Layer

  • domain.ts: 엔터티와 상태 타입
  • state.ts: 티켓번호, 대기 승급, 리포트 계산
  • repository.ts: 저장소 추상화
  • schema.ts: PostgreSQL 확장용 Drizzle 스키마

9. 데이터 관계 다이어그램

관계 설명
Member 1 → N Visit 한 회원은 여러 번 방문할 수 있고, 방문 단위로 접수와 이용 흐름이 시작된다.
Visit 0..1 → QueueEntry 공간 이용 또는 즉시 이용은 대기 엔트리가 없을 수 있고, 대기 발생 시 하나의 대기 엔트리가 연결된다.
Visit 0..1 → Session 관리자가 결제 확인 후 시작 처리한 방문만 세션을 가진다.
Visit 0..N → Payment 최초 결제, 연장 결제, 조정 기록이 같은 방문에 누적된다.
Resource 1 → N Session 한 자원은 시간에 따라 여러 세션을 가질 수 있지만 같은 시각에는 활성 세션 하나만 허용한다.
Visit 0..N → TTSEvent 입장 가능, 종료 임박, 시간 종료 등의 호출 이벤트가 방문 기준으로 생성된다.

10. 주요 시퀀스

유료 콘텐츠 접수

  1. 키오스크가 회원 입력 또는 기존 회원 선택을 받는다.
  2. 각 단계는 태블릿 한 화면 안에서 교체되며 이전 단계 UI는 아래에 남기지 않는다.
  3. enqueueVisit이 방문과 티켓번호를 만든다.
  4. 열린 대기와 빈 자원을 기준으로 즉시 이용 또는 대기 등록을 결정한다.
  5. 대기 등록이면 QueueEntry를 생성하고 FIFO 순서를 재계산한다.
  6. 관리자 화면과 보드는 다음 폴링에서 같은 스냅샷을 확인한다.

결제 후 시작

  1. 관리자가 외부 서울시 결제시스템에서 결제를 직접 처리한다.
  2. recordPayment로 운영용 결제 기록을 남긴다.
  3. startSession 또는 startWalkInSession이 자리 중복과 결제 기록을 확인한다.
  4. 세션 시작 시 종료 예정 시각을 계산하고 방문 상태를 in_session으로 바꾼다.
  5. 종료, 연장, 노쇼 처리 결과는 활동 로그와 리포트에 반영된다.

11. 수용 기준

사용자 관점

  • 학생 또는 보호자는 키오스크에서 스스로 접수할 수 있다.
  • 키오스크는 한 화면에 현재 단계 하나만 보여준다.
  • 다음 단계는 이전 단계 아래에 쌓이지 않고 화면 전환으로 표시된다.
  • 뒤로가기는 상단의 작은 보조 버튼으로 제공된다.
  • 접수 완료 후 즉시 이용인지 대기인지 명확하게 안내한다.
  • 30초 무반응 시 첫 화면으로 돌아간다.

운영자 관점

  • 자원별 대기열과 현재 이용 상태를 한 화면에서 확인한다.
  • 결제 기록 없이는 세션 시작이 불가능하다.
  • 빈 자리가 생기면 다음 대기자를 호출할 수 있다.
  • 일마감 리포트에서 방문, 매출, 이용률을 확인한다.
