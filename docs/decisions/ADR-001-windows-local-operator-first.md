# ADR-001: Windows 로컬 서버와 운영자 중심 관리자 화면을 사용한다

## Status

Accepted

## Date

2026-05-11

## Context

autoPAN은 공공기관 현장에서 사용하는 내부 운영 시스템이다. 클라우드 비용은 증빙과 승인 부담이 있고, 실제 사용자는 서버, 터미널, 데이터베이스 지식이 없는 직원이다.

현장 장비 조건은 다음과 같다.

- Windows 노트북 1대를 서버로 사용한다.
- 전용 공유기 기반 내부망에서만 접속한다.
- 학생과 보호자는 태블릿에서 `/kiosk`를 사용한다.
- 직원은 데스크톱 또는 노트북에서 `/admin`을 사용한다.
- 데이터는 현장 서버에 보관한다.

## Decision

v2 운영 구조는 Windows 노트북 로컬 서버, 전용 공유기 내부망, 운영자 중심 관리자 화면으로 설계한다.

관리자는 데이터베이스를 직접 보거나 수정하지 않는다. `/admin`은 원본 테이블을 보여주는 DB 관리 화면이 아니라 오늘 운영, 대기/호출, 결제/시작, 현재 이용, 회원, 일마감, 설정으로 구성된 업무 화면이다.

운영 저장소는 우선 SQLite 파일 저장을 목표로 한다. PostgreSQL은 다중 센터, 전문 운영자, 더 큰 동시성 요구가 생길 때 전환 대상으로 둔다.

## Alternatives Considered

### Cloud hosting

- Pros: 외부 접속, 관리형 인프라, 백업 자동화가 쉽다.
- Cons: 공공기관 비용 증빙과 승인 부담이 있다. 외부망 보안 검토가 커진다.
- Rejected: 현재 현장 요구는 내부망 운영이며 클라우드 비용 처리가 어렵다.

### Public Wi-Fi directly

- Pros: 별도 장비가 적다.
- Cons: 기기 간 통신 차단, 접속 인증, IP 변경, 보안 문제가 생길 수 있다.
- Rejected: 키오스크, 직원 PC, 서버가 안정적으로 서로 접속해야 한다.

### PostgreSQL first

- Pros: 정석적인 서버 DB이며 확장성이 높다.
- Cons: Windows 현장 운영, 백업, 복구, 서비스 관리가 어렵다.
- Rejected for v2: 현재 규모에서는 운영 난이도가 더 큰 리스크다.

### Raw database admin screen

- Pros: 개발자가 빠르게 만들 수 있다.
- Cons: 운영자가 실수하기 쉽고 DB 지식이 필요하다. 개인정보 노출과 데이터 손상 위험이 커진다.
- Rejected: 시스템 목적은 DB 관리가 아니라 현장 운영이다.

## Consequences

- 운영자는 브라우저 화면만 사용한다.
- 개발자는 DB 테이블을 업무 상태로 변환하는 서비스 계층을 명확히 유지해야 한다.
- 백업과 복구는 파일 기반 절차로 단순화한다.
- `/maintenance`는 일반 관리자 화면과 분리해야 한다.
- 나중에 PostgreSQL로 전환할 수 있도록 저장소 인터페이스를 분리해야 한다.

## Follow-up Work

- SQLite 운영 저장소 구현
- Windows 자동 실행 스크립트 작성
- 관리자 PIN과 유지보수 PIN 추가
- 백업 상태 표시
- 전용 공유기 운영 문서 작성
